## Update Incodex

```bash
inc update --dry-run
inc update
```

Homebrew installations use Homebrew. macOS script and managed Windows installations use their verified platform installer. The installed CLI then publishes its bundled Runtime. Updating does **not** patch or re-sign Codex. Even a current-version script update repairs Runtime.

If CLI replacement succeeds but Runtime publication fails, the result is partial success; retry the Runtime stage or update after resolving the reported error. Do not assume the old CLI was restored. Use [status](/en/commands/status/) and [doctor](/en/commands/doctor/) to compare the selected and bundled Runtime.

Source installations update with `git pull` and `cargo install --locked --path crates/incodex-cli`.

## Windows v1.5.13 (unreleased): update recovery and the private-window notice

On Windows, `inc update` updates the CLI and publishes its bundled Runtime; it does not replace the installed native Store helper. To activate the v1.5.13 prearm target-generation fix, quit Codex normally, then run `incodex uninstall` followed by `incodex install` once against the current Store package. This explicit migration installs the updated helper; `inc update` alone does not.

The fix handles a newer staged Store package replacing an earlier target from the same update source. Automatic Store-update recovery remains experimental, and the first window after a real Store update has not been verified.

The private-window notice supports both older and newer official Banner components, reusing Codex's own layout, styling and dismissal action.

## Windows v1.5.4

`inc update` preserves an installed helper's authorization and hands pending Store-update records from the same installation to the verified Runtime, including same-version repair, without replacing a compatible helper or restarting Codex.

If a previous update has already left pending records from a different installation operation, Runtime synchronization reports failure and retains them. Quit Codex normally, run `incodex uninstall`, then `incodex install` to refresh integration explicitly; this migration does not count as a successful automatic update. See the [v1.5.4 release notes](/en/releases/v1.5.4/).

If `install` reports an existing enabled integration, first run `incodex uninstall --dry-run`, then `incodex uninstall`; preview `incodex install --dry-run` and run `incodex install` again. Keep Codex fully closed during both operations. This is an explicit integration migration, not successful automatic recovery or an in-place update.

## Upgrade from v1.5.0

Run `inc update` to update the CLI and publish its bundled Runtime. If an earlier `incodex install` reported that the helper source was not a regular file and automatic recovery was unavailable, run `incodex install` again against the current app. `inc update` does not create the missing registration. See the [v1.5.1 release notes](/en/releases/v1.5.1/).

## Upgrade from v1.4.0

For Homebrew, script or managed Windows installations, run `inc update`. For a source installation, update your checkout with `git pull`, then run `cargo install --locked --path crates/incodex-cli` and `incodex runtime`.

To migrate an existing ad-hoc-signed default macOS integration to the persistent local signing identity, finish active work, then explicitly run `incodex uninstall` followed by `incodex install` once. The new identity may need an initial grant. Repeat the original `--app <path>` or `--clone` option when reinstalling those targets. If you only use `incodex open`, update and reopen your private window; no app integration is needed. Compatible UI/action changes apply to supported running windows; other Runtime changes require reopening and native/helper/loader changes require installation. Already-open incognito windows retain their privacy Runtime until normal close.

See [Runtime updates](/en/commands/runtime/) and the [v1.5.0 release notes](/en/releases/v1.5.0/).

## Upgrading to v1.2.1

An older macOS app integration needs `incodex uninstall`, then `incodex install`, to replace its loader and use this release's startup fix. `inc update` alone does not replace that loader.

Windows app integration adds an experimental current-user login observer; `incodex uninstall` removes that entry and stops it. The first cold launch after a real Store update remains unverified.

See the [v1.2.1 release notes](/en/releases/v1.2.1/) and [release history](/en/releases/).

## After an official Codex update

The registered default macOS install attempts to restore its integration after an official Sparkle update. If recovery is unavailable or the integration remains missing, run `incodex install` against the **current** app. `--app` and `--clone` do not use this recovery path.

After an official Windows Store update, fully quit Codex and run `incodex install` against the **current** package generation. To activate the v1.5.13 prearm helper fix, use the explicit `incodex uninstall` then `incodex install` migration described above. Automatic Store-update recovery remains experimental; the first cold launch after a real Store update is unverified.

A Runtime-only update uses `incodex runtime`. After the v1.5.0 setup above, compatible UI/action changes can apply live; other Runtime changes load after reopening. It does not replace an outdated app loader. On macOS, an older installed loader that prevents `open` needs `incodex uninstall`, then `incodex install`.

## Permission check after updates

After successful Runtime publication or official-update recovery, macOS schedules one bounded permission check. It reuses the installed host probe and shared guide. Confirmed missing access opens the guide; two fresh grants skip it. Unknown results stay pending and do not count as denial. The automatic check never opens or quits Codex, resets permissions, or opens System Settings. It does not promise permission continuity across signing changes.

The preflight check lasts at most 30 seconds. Once the card opens, completing System Settings has no authorization countdown; users can skip or close it. After a normal restart, the guide reads fresh permissions instead of reusing the previous process’s readings. The remaining macOS 26 check is the full two-row guide in an installed ChatGPT window: grant missing permissions in System Settings, return to ChatGPT, and confirm fresh probes close the guide. See [permissions](/en/permissions/).

## Remove integration or the CLI

`incodex uninstall` removes app integration. On macOS, it verifies and restores the matching original app; it will not overwrite an already-upgraded official package with an older backup. A successful verified restore deletes that backup. The backup lives under `~/.incodex/transactions/<install-id>/original/ChatGPT.app`; later successful installs also prune superseded terminal backups for the same app.

`incodex self-uninstall` removes the supported managed CLI. Add `--restore-app` to remove integration first. For Homebrew, use `brew uninstall incodex`; for Cargo, use `cargo uninstall incodex-cli`. Removing the CLI alone does not restore app integration.

Interrupted macOS mutations use [recover](/en/commands/recover/) with the exact transaction ID. Do not manually replace the app or delete journals.
