## Finder entry

`incodex launch` creates or refreshes `/Applications/ChatGPT - Inc.app`. Use **Launch** in the `inc` menu to create or open this normal-window route; **Open** starts a private window directly.

In Finder, choose **Go › Go to Folder**, enter `/Applications`, and press Return. Open **ChatGPT - Inc.app** there.

Use `incodex launch --remove --dry-run` to preview removal of the launcher, then `incodex launch --remove` to confirm. This does not uninstall app integration or close Codex. See the [launch guide](/en/commands/launch/) for creation, reuse, removal, and platform limits.

### Migrate older user-folder entries

After it publishes and verifies the shared entry, `incodex launch` migrates only exact Incodex-owned entries from `~/Applications/ChatGPT - Inc.app` and `~/Applications/Incodex Launcher.app`. It keeps unknown, modified, or other-user entries. If migration cannot remove an old entry, the new shared entry remains and the CLI reports the retained path. It does not create `/Applications`, fall back to a user entry, or request `sudo`.

Do not remove either old path by hand before the new entry is published. The command checks ownership before it removes an entry.

## Launcher icon

The launcher follows the selected ChatGPT or Codex Dock icon style. If that icon resource is unavailable, it falls back to the host's file icon. The **INCODEX** glass plaque stays on the launcher. Incodex does not copy or modify the official host app.

<figure>
  <img src="/incodex/images/launcher-icon-design-v3.png" alt="Design comparison of the INCODEX plaque on ChatGPT, Codex Light, and Codex Dark icons at several sizes" />
  <figcaption>Design comparison of the INCODEX plaque on ChatGPT and Codex icons at several sizes.</figcaption>
</figure>

Run `inc update`, then `incodex launch` to publish the launcher. Each `incodex launch` run, including opening the existing launcher, reads the selected Dock icon style again. Run it again after changing the Dock choice. Incodex does not watch for icon changes in the background. Updating the launcher does not require re-signing, reinstalling, or restarting the host. `incodex launch --remove` removes the Incodex launcher, even when its source host is gone. It does not uninstall app integration or close Codex.

## Install shortcuts

```bash
curl -fsSL https://raw.githubusercontent.com/daftAI2026/incodex/main/scripts/setup-quick-launchers.sh | bash
```

The script writes Raycast commands to `~/Library/Application Support/Raycast/script-commands`. Only when Alfred is detected does it generate a standard `.alfredworkflow` and open Alfred's normal import confirmation.

## Raycast setup

- **v2:** Settings → Script Commands → Add Script Directory.
- **v1:** Settings → Extensions → **+** → Add Script Directory.

Choose the script-commands directory above, then run **Reload Script Commands**.

Settings vary by Raycast version; see the [official Script Commands guide](https://manual.raycast.com/script-commands).

Open launches the private window directly. Status and Doctor use Raycast's fullOutput when it provides a usable TERM; otherwise they launch a supported terminal. `INCODEX_LAUNCHER_APP` can select Terminal, iTerm2, Alacritty, kitty, WezTerm, Ghostty, Hyper, WindTerm, or Warp. A failed selected launch falls back to Terminal.

These shortcuts are optional and macOS-only. See [permissions](/en/permissions/).

**macOS:** the CLI uses WindowServer observation for close/minimize; Accessibility permission is not required. Installed-app permissions remain separate.
