## Finder entry

### Current stable v1.5.8 entry

The stable macOS `incodex launch` command creates `~/Applications/ChatGPT - Inc.app` in your user Applications folder. Its icon uses the selected host's current system file icon with an **INCODEX** glass plaque. It does not follow the separate Dock icon preference for ChatGPT/Codex. The official host bundle remains unchanged. Use **Launch** in the `inc` menu to create or open this normal-window route; **Open** starts a private window directly.

In Finder, choose **Go › Go to Folder**, enter `~/Applications`, and press Return. Open **ChatGPT - Inc.app** there.

Use `incodex launch --remove --dry-run` to preview removal of the stable launcher, then `incodex launch --remove` to confirm. This does not uninstall app integration or close Codex. See the [launch guide](/en/commands/launch/) for creation, reuse, removal, and platform limits.

## Unreleased: move the entry to `/Applications`

An unpublished migration candidate publishes `/Applications/ChatGPT - Inc.app`. The candidate entry appeared in Finder; macOS `open` reopened the existing Codex host. Removal and recreation also succeeded. This path is not in the stable CLI: v1.5.8 still creates the user-folder entry shown above.

<figure>
  <img src="/incodex/images/launcher-applications-entry.png" alt="Finder example of the unpublished ChatGPT - Inc launcher in Applications" />
  <figcaption>Unreleased candidate example: ChatGPT - Inc in `/Applications`.</figcaption>
</figure>

The candidate verifies the destination before retiring exact Incodex-owned entries at `~/Applications/ChatGPT - Inc.app` and `~/Applications/Incodex Launcher.app`. It does not create `/Applications`, fall back to a user entry, or request `sudo`. It rejects entries owned by another user and keeps unknown or modified same-name apps. If old-entry removal fails, the published system entry remains and the CLI reports the retained old path.

## Host-based launcher icon

The v1.5.8 launcher uses the host's current system icon with an **INCODEX** glass plaque at the bottom. It does not copy or modify the official app, and users do not need Icon Composer. ChatGPT and Codex keep their own marks instead of receiving one fixed replacement image.

<figure>
  <img src="/incodex/images/launcher-icon-design-v3.png" alt="Design comparison of the INCODEX plaque on ChatGPT, Codex Light, and Codex Dark icons at several sizes" />
  <figcaption>Design comparison of the INCODEX plaque on ChatGPT and Codex icons at several sizes.</figcaption>
</figure>

Run `inc update`, then `incodex launch` to create or update the launcher. Each `incodex launch` run, including opening the existing launcher, reads the host's current system file icon. Run it again after that icon changes. Incodex does not watch for icon changes in the background. The launcher does not follow the separate Dock icon preference for ChatGPT/Codex, and updating it does not require re-signing or reinstalling the host. Recognized older launchers remain upgradable and removable. `incodex launch --remove` removes the Incodex launcher, even when its source host is gone. It does not uninstall app integration or close Codex.

## Install shortcuts

```bash
curl -fsSL https://raw.githubusercontent.com/daftAI2026/incodex/main/scripts/setup-quick-launchers.sh | bash
```

The script writes Raycast commands to `~/Library/Application Support/Raycast/script-commands`. Only when Alfred is detected does it generate a standard `.alfredworkflow` and open Alfred's normal import confirmation.

## Raycast setup

- **v2:** Settings → Script Commands → Add Script Directory.
- **v1:** Settings → Extensions → **+** → Add Script Directory.

Choose the script-commands directory above, then run **Reload Script Commands**.

Settings vary by Raycast version; see the [official Script Commands guide](https://manual.raycast.com/script-commands).

Open launches the private window directly. Status and Doctor use Raycast's fullOutput when it provides a usable TERM; otherwise they launch a supported terminal. `INCODEX_LAUNCHER_APP` can select Terminal, iTerm2, Alacritty, kitty, WezTerm, Ghostty, Hyper, WindTerm, or Warp. A failed selected launch falls back to Terminal.

These shortcuts are optional and macOS-only. See [permissions](/en/permissions/).

**macOS:** the CLI uses WindowServer observation for close/minimize; Accessibility permission is not required. Installed-app permissions remain separate.
