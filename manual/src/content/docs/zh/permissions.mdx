## 稳定版 v1.5.0：应用权限

默认 `install` 会重新打开 ChatGPT，分别检查辅助功能和屏幕录制。原生向导显示独立的两行。两项均已授权时不会出现授权卡；确认任一项缺失时，向导会自动打开。默认 `uninstall` 也会通过该向导检查已恢复的官方应用。官方应用没有 Incodex 探针时，屏幕录制保持 `unknown`。

![macOS 安装向导中的辅助功能行实窗截图](/incodex/images/accessibility-guide.png)

图中只展示辅助功能行，不是双行向导全貌。向导语言跟随本地 Codex 设置。点击**允许**，把 ChatGPT 应用行拖进**系统设置 → 隐私与安全性 → 辅助功能（无障碍）**列表并开启权限，完成 macOS 认证。向导自动检查；两项确认授权后自动关闭。macOS 12 对应**系统偏好设置 → 安全性与隐私 → 隐私 → 辅助功能**。

返回可回到初始卡；跳过或关闭只留下未完成的权限设置，不撤销安装。运行 `incodex perm` 或 `inc perm` 可继续；`accessibility` 和 `permissions` 都不是别名。见 [perm 命令页](/zh/commands/perm/)。明确选择辅助功能“允许”后，只有锁内新鲜读数仍确认缺权时，才重置 ChatGPT 的旧辅助功能登记。相同 bundle ID 的应用副本共享该登记范围。`--app` / `--clone` 不触发默认自动交接。

## 屏幕录制与 `perm`

运行 `incodex perm` 或 `inc perm` 检查两项权限并继续设置。该命令没有 `accessibility` 或 `permissions` 别名。默认 `/Applications/ChatGPT.app` 向导并列显示“辅助功能”和“屏幕录制”两行。某项已授权时仍保留该行，并显示本地化完成标签与 `✓` 标记（英文为 `Done ✓`）。CLI 只有在新鲜探针确认两项均为 `granted` 后才报告完成。

向导在 macOS 26 及更早版本保留现有名称和图标。macOS 27 及以后版本从当前系统读取权限名称和图标：简体中文名称为“设备控制和数据访问”和“录屏与系统录音”，前者使用蓝色文件夹与齿轮图标。名称按向导语言选择；系统未提供该语言时采用 Apple 英文名称，资源缺失时保留内置回退。这只改变呈现，不改变权限检测、设置跳转或授权动作。macOS 26 的真实窗口和跨签名授权连续性仍待验收。

录屏探针运行在注入到正常 ChatGPT Electron 主进程的模块中，并调用公开 API `systemPreferences.getMediaAccessStatus('screen')`。探针本身只读取权限状态，不请求截图或录音，不重置 `ScreenCapture`，也不修改供应商 CUA 侧车。此权限与终端或启动程序的辅助功能权限分开，也不是 `incodex open` 的前置条件。

明确选择屏幕录制行的“允许”后，向导在既有 App 锁内复验目标。只有新鲜读数仍确认缺权时，每次向导才重置一次 ChatGPT 的旧 `ScreenCapture` 登记，然后打开设置。这会清除过期签名要求，不会授予权限。已授权或 `unknown` 不触发重置；重试只重开设置。用户仍需添加或启用当前 `/Applications/ChatGPT.app`。若 macOS 要求，请正常退出并重新打开 ChatGPT。完成仍须由当前宿主的新鲜读数确认。

恢复官方应用或 Runtime 缺失时，探针证据保持 `unknown`；不得标成已授权或已拒绝。权限读数只代表当前宿主代际，更新后会重新检查。

## 独立 open：终端或启动程序的辅助功能

`incodex open` 需要的是**运行命令的终端或启动程序**的辅助功能权限，用来区分关窗与最小化。这与 ChatGPT 的权限不同。开启 macOS 提示的对应程序后重试；检查发生在创建会话之前。`open --dry-run` 不请求权限。

## 钥匙串

macOS 改包后签名变化，系统可能询问应用是否可访问 **Codex Storage Key**。确认应用和项目名称匹配后，再输入 **Mac 登录密码**；希望保留授权时选择**始终允许**。允许或仅允许一次可能以后再询问；不匹配的请求选拒绝。不要把密码输入 Incodex 或 Terminal。

## 远控设备密钥

v1.3.4 起：普通已安装集成的 macOS 宿主，在官方远控模块请求系统保护、不可导出的 P-256 密钥并报 `-34018` 时，可以使用限定范围的传统登录钥匙串兼容路径。先尝试原始 Security 调用。仅硬件密钥请求、无痕窗口和 Windows 不进入此路径；官方模块及授权 API 保持原样。

兼容路径检查实际私钥不可导出，并保留系统访问控制列表，但**不保留 Secure Enclave、Data Protection Keychain 或 ThisDeviceOnly 的保护语义**。之后签名身份变化可能需要重新允许系统钥匙串访问。不会自动迁移、轮换或删除已有不可访问密钥。本地创建、读取、签名和删除已通过测试，候选 Runtime 的真实远控授权也已验证成功；重签后的钥匙串授权连续性尚未验收。

稳定本地签名身份使已登记的默认安装可在官方 Sparkle 更新后尝试恢复。兼容适配只接受原有临时签名宿主，或严格验签且叶证书匹配既有私有目录内公开证书登记的宿主。共享身份校验不授予辅助功能、Storage Key 或远控权限。每项能力保留独立检查；不新增身份库或权限服务。原生适配变化需彻底退出并重开，不能仅靠 Runtime 界面热更新。跨签名授权连续性仍未验收。

## 其他权限与智能快照

钥匙串授权和 Computer Use 权限不能证明辅助功能已就绪。屏幕与系统音频录制是另一项 macOS 权限。向导将屏幕录制作为独立一行展示；修改它不能修复辅助功能授权。

修改后的 macOS 包无法保留有效的 OpenAI 签名。安装后官方 **Appshot／智能快照**的拍照和截图附件不可用，这不是相机权限没开。[卸载集成](/zh/commands/uninstall/)恢复官方包后可恢复；不改包的 [open](/zh/commands/open/) 路径不会改变应用签名。
