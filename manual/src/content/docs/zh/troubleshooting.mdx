## 先读取诊断

```bash
incodex --version
incodex status --json
incodex doctor --json
```

这些命令不会修复或请求权限。macOS 的 `doctor --deep` 增加 nested 签名、entitlement 与 Gatekeeper 证据。安装后临时签名是预期状态；仅凭 Gatekeeper 输出不能判断安装失败。

## macOS 安装后拒绝启动

v1.3.1 已修复：Codex 26.1007.21159 带有临时签名无法保留的通信通知受限权限。此前受影响的安装可能通过签名验证，却以 Code 163 拒绝启动。运行 `inc update`；若已遇到此问题，先运行 `incodex uninstall` 恢复官方应用，再运行 `incodex install`。仅更新 CLI 和 Runtime 不会重新签名应用。此问题不能用来解释 dots 的 HTTP 409。

## macOS 远控授权在打开网页前失败

尚未发布，计划纳入 v1.3.3：已安装集成的 macOS 宿主在官方远控模块创建不可导出密钥报缺失权限（`-34018`）时，可以尝试兼容路径。运行 `inc update`，彻底退出并重开 Codex，再重试授权。更新 Runtime 不会重新签名 Codex；官方应用升级后仍需先对当前包重新安装集成。

此修复针对本地设备密钥创建，不代表修复 dots HTTP 409 或所有远控故障。官方网页和云端认证流程继续保留。本地密钥创建与签名已通过测试，候选 Runtime 的真实远控授权也已验证成功；不会自动迁移或删除已有不可访问密钥。钥匙串保护边界见[权限说明](/zh/permissions/)。

## 更新后没有帽子眼镜

检查集成是否安装、当前选中了哪份 Runtime。`incodex runtime` 后彻底退出再重开；官方包升级后对当前代重新 install。仅发布 Runtime 不会安装应用入口。

## 安装没有弹授权卡

只有默认 macOS 安装发现 ChatGPT 辅助功能缺失时才弹卡。已有有效权限不需要卡。想主动检查并继续设置，用 `incodex accessibility`，不要重置其他权限。

## open 失败或等待异常久

读取终端结果，检查官方应用本身的启动和网络。macOS 检查启动终端的辅助功能；Windows 用 doctor 检查当前用户的 Store 包。重试不能成为复制包、删除官方配置或绕过归属校验的理由。

## 语言或首次问卷异常

私密窗口应继承日常 Codex 的语言和配置。先对比主应用。重复异常请提供 CLI 版本、官方版本、入口和脱敏诊断，不要公开 auth.json、配置秘密、聊天数据库或私人日志。首次问卷不是预期的私密窗口行为。

## Windows 安装拒绝正在运行的应用

先完成任务，用 Ctrl+Q 或托盘 Quit 退出，再重试。Incodex 不会强制结束官方应用。实验中的 Store 更新观察不保证更新后首次冷启动成功。

## 会话残留或安装中断

读取 doctor，不要删除日常 `~/.codex` 数据库。macOS 修改中断，用准确事务的 [recover](/zh/commands/recover/)。不确定的状态会保留，不会盲目销毁。

## 寻求帮助

[提交项目 issue](https://github.com/daftAI2026/incodex/issues) 时附脱敏事实；漏洞按 [SECURITY.md](https://github.com/daftAI2026/incodex/blob/main/SECURITY.md)处理，不要公开提 issue。
