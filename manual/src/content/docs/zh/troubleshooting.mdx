## 先读取诊断

```bash
incodex --version
incodex status --json
incodex doctor --json
```

这些命令不会修复或请求权限。macOS 的 `doctor --deep` 增加 nested 签名、entitlement 与 Gatekeeper 证据。安装后临时签名是预期状态；仅凭 Gatekeeper 输出不能判断安装失败。

## macOS 安装后拒绝启动

Codex 构建 26.1007.21159 带有临时签名无法保留的通信通知受限权限。受影响的旧安装可能通过签名验证，却以 Code 163 拒绝启动。运行 `inc update`；若已遇到此问题，先运行 `incodex uninstall` 恢复官方应用，再运行 `incodex install`。仅更新 CLI 和 Runtime 不会重新签名应用。此问题不能用来解释 dots 的 HTTP 409。

## macOS 远控密钥创建在打开网页前失败

此恢复步骤适用于官方远控模块创建本地密钥时报告缺少权限（`-34018`）的既有传统登录钥匙串回退。运行 `inc update`，彻底退出并重开 Codex，再重试授权。更新 Runtime 不会重新签名 Codex。Sparkle 更新后，已登记的默认安装会尝试恢复；若集成仍缺失，请针对当前应用运行 `incodex install`。`--app` 和 `--clone` 使用原有安装流程。这些启动步骤只描述密钥创建，不描述下方独立的候选签名路径。

此修复针对本地设备密钥创建，不代表修复 dots HTTP 409 或所有远控故障。官方网页和云端认证流程继续保留。此前本地创建和签名测试已通过；较早的候选 Runtime 也完成过一次真实远控授权。这些结果不代表下方的新签名等待候选已验收。不会自动迁移或删除已有不可访问密钥。钥匙串保护边界见[权限说明](/zh/permissions/)。

**稳定本地签名身份：**兼容适配接受原有临时签名宿主，或严格验签且叶证书匹配私有公开证书登记的宿主。身份检查不授予辅助功能、Storage Key 或远控权限。迁移既有临时签名的默认 macOS 安装时，显式运行一次 `incodex uninstall`，再运行 `incodex install`；新身份可能需要首次授权。不要为修复身份检查而重置权限或重建设备 ID。跨签名授权连续性仍未验收。

## 候选：macOS 设备密钥签名等待系统授权

此签名等待行为**不包含在稳定版 v1.5.9**。它只适用于官方模块现有的系统保护、不可导出 P-256 设备密钥公钥与签名操作。其他密钥和 API 仍走官方路径。候选通过实时 Runtime 动作路径激活，设计上不要求重启宿主。界面或代际确认只证明动作与界面代际已提交，不证明原生适配器就绪或钥匙串授权成功。不要把上方密钥创建恢复步骤套用到此签名路径。

macOS 显示授权对话框时，请核对应用和请求。**Mac 登录密码只输入系统对话框**。确认适当后，可对当前密钥与 helper 选择“始终允许”。这不是永久或全密钥授权保证；其他密钥或已更换的 helper 可能需要单独授权。相同密钥与 helper 未变却反复弹窗时，不要视为正常；请核对请求使用的密钥和 helper。

公钥请求、helper 校验和完整请求传输仍受五分钟机器期限限制。helper 收到完整签名请求后，候选会等待系统或 helper 返回结果，或等待宿主退出；期限不再终止这项授权等待。拒绝和取消不会自动重试，候选不会切换到另一签名器。

本地签名成功不证明远控注册、连接或服务器接受请求。远端环境离线提示不能确定本机钥匙串授权失败。请以官方远控状态确认注册或连接是否完成。

## 更新后没有帽子眼镜

检查集成是否安装、当前选中了哪份 Runtime。运行 `inc update` 更新 CLI 并发布内置 Runtime。兼容的 UI 与动作变化可在线应用，其他 Runtime 变化需重开。已登记的默认 macOS 安装会尝试在 Sparkle 更新后恢复；若入口仍缺失，请针对当前应用运行 `incodex install`。仅发布 Runtime 不会安装应用入口。

## 安装没有弹授权卡

向导会分别检查辅助功能与屏幕录制。运行 [`incodex perm`](/zh/commands/perm/) 或 `inc perm` 可继续；`accessibility` 和 `permissions` 都不是别名。向导只对确认缺权出卡；`unknown` 保持待确认。重置须用户明确选择“允许”，并且锁内新鲜复验仍确认缺权。不要重置其他权限。

## open 失败或等待异常久

读取终端结果，检查官方应用本身的启动和网络。macOS 检查启动终端的辅助功能；Windows 用 doctor 检查当前用户的 Store 包。重试不能成为复制包、删除官方配置或绕过归属校验的理由。

## 语言或首次问卷异常

私密窗口应继承日常 Codex 的语言和配置。先对比主应用。重复异常请提供 CLI 版本、官方版本、入口和脱敏诊断，不要公开 auth.json、配置秘密、聊天数据库或私人日志。首次问卷不是预期的私密窗口行为。

## Windows 安装拒绝正在运行的应用

先完成任务，用 Ctrl+Q 或托盘 Quit 退出，再重试。Incodex 不会强制结束官方应用。实验中的 Store 更新观察不保证更新后首次冷启动成功。

## 会话残留或安装中断

读取 doctor，不要删除日常 `~/.codex` 数据库。macOS 修改中断，用准确事务的 [recover](/zh/commands/recover/)。不确定的状态会保留，不会盲目销毁。
