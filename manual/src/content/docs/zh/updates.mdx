## 更新 Incodex

```bash
inc update --dry-run
inc update
```

Homebrew 安装沿用 Homebrew；macOS 脚本和受管理 Windows 安装使用经过校验的平台安装器。随后由已安装 CLI 发布内置 Runtime。更新**不会**修改或重新签名 Codex；脚本安装即使版本已最新，也会修复 Runtime。

CLI 更换成功但 Runtime 发布失败时，会报告部分成功。解决输出中的错误后重试 Runtime 或更新，不要以为旧 CLI 已自动恢复。用 [status](/zh/commands/status/) 和 [doctor](/zh/commands/doctor/) 核对选中的 Runtime 与 CLI 内置产物。

源码安装用 `git pull` 和 `cargo install --locked --path crates/incodex-cli` 更新。

## 从 v1.4.0 升级

Homebrew、脚本或 Windows 受管理安装运行 `inc update`。源码安装先在代码仓运行 `git pull`，再执行 `cargo install --locked --path crates/incodex-cli` 和 `incodex runtime`。

将既有临时签名的默认 macOS 集成迁移到持久本地签名身份时，先完成手头工作，再显式运行一次 `incodex uninstall` 和 `incodex install`。新身份可能需要首次授权。重装 `--app <path>` 或 `--clone` 目标时，带上原选项。只使用 `incodex open` 的用户更新后重开隐身窗口即可，无需应用集成。兼容的 UI 与动作变化可应用到受支持的运行中窗口；其他 Runtime 变化仍需重开，原生 helper 或加载器变化需要重新安装。已打开的隐身窗口保留原隐私 Runtime，直到正常关闭。

见 [Runtime 更新](/zh/commands/runtime/) 和 [v1.5.0 版本说明](/zh/releases/v1.5.0/)。

## v1.2.1 的升级注意事项

macOS 旧版安装集成需要先 `incodex uninstall`，再 `incodex install`，更新应用内加载器后才能使用本轮启动修复。仅运行 `inc update` 不会替换这个加载器。

Windows 应用集成增加了实验性的当前用户登录观察程序；`incodex uninstall` 会移除该入口并停止它。真实 Store 更新后的首次冷启动仍未验收。

见 [v1.2.1 版本说明](/zh/releases/v1.2.1/) 和[历史版本](/zh/releases/)。

## 官方 Codex 更新后

已登记的 macOS 默认安装会尝试在官方 Sparkle 更新后恢复集成。若恢复不可用或集成仍缺失，请针对**当前应用**运行 `incodex install`。`--app` 和 `--clone` 不使用此恢复路径。

官方 Windows Store 更新后，完全退出 Codex，再针对**当前包代际**运行 `incodex install`。Store 自动恢复仍属实验能力；真实更新后的首次冷启动尚未验收。

只更新 Runtime 用 `incodex runtime`。完成上方 v1.5.0 设置后，兼容的 UI 与动作变化可在线应用，其他 Runtime 变化重开后加载。它不会替换过期的应用加载器。macOS 旧版已安装加载器妨碍 `open` 时，先 `incodex uninstall`，再 `incodex install`。

## 更新后检查权限

Runtime 发布或官方更新恢复成功后，macOS 会安排一次有界权限检查。检查复用已安装宿主探针和共用向导。确认缺权时打开向导；新鲜读数确认两项已授权时跳过。`unknown` 保持待确认，不当作拒绝。自动检查不会打开或退出 Codex、重置权限或打开系统设置，也不承诺跨签名授权连续。

预检最多 30 秒。卡片出现后，用户完成系统设置没有倒计时；可随时跳过或关闭。正常重启后，向导会读取新权限，不沿用上个进程的读数。macOS 26 的真实窗口仍未验收；见[权限说明](/zh/permissions/)。

## 移除集成或 CLI

`incodex uninstall` 移除应用集成。macOS 会验证并恢复匹配的原包，不会用旧备份覆盖已经升级的官方包。验证恢复成功后删除备份。备份位置是 `~/.incodex/transactions/<install-id>/original/ChatGPT.app`；后续成功安装也会清理同一应用已被取代的终态备份。

`incodex self-uninstall` 移除支持的受管理 CLI。加 `--restore-app` 先移除集成。Homebrew 用 `brew uninstall incodex`，Cargo 用 `cargo uninstall incodex-cli`。只卸 CLI 不会恢复应用集成。

macOS 修改中断时，用 [recover](/zh/commands/recover/) 指定准确事务 ID，不要手动换包或删除 journal。
